# Стройка века: правила игрового прототипа

> Перед каждой итерацией Codex должен сверяться с этим файлом.
> После каждой итерации, если в задании были явно указаны изменения, связанные с игрой, Codex должен обновить этот файл.

## Питч

`Стройка века` - короткая Shikaku-like puzzle-игра внутри CV-лендинга. Игрок размечает прямоугольные участки на генплане, закладывает фундамент и превращает пустую строительную сетку в советский ретро-футуристический город будущего.

## Core Loop

1. Игрок видит клеточное поле и `План пятилетки`.
2. Игрок зажимает клетку и тянет прямоугольник.
3. Во время drag виден фундамент и площадь участка римской цифрой.
4. После отпускания корректный участок превращается в здание.
5. Игрок закрывает все проекты из плана и заполняет обязательные клетки.
6. После победы открывается следующий генплан.

## Правила Постройки

- Выделение всегда прямоугольное.
- Площадь выделения должна совпасть с одним из проектов в плане.
- Римская цифра показывает площадь проекта: `IV` = 4 клетки, `VI` = 6 клеток.
- Если выделение начинается вне здания и валидно пересекает старые здания, старые здания идут под снос, а новое строится.
- Если выделение начинается вне здания и невалидно, состояние поля не меняется.
- Ошибки дают мягкий feedback: `Площадь не по плану`, `Нельзя строить на пустыре`.

## Удаление И Снос

- Если drag начинается внутри уже построенного здания, игра переходит в режим удаления.
- Для удаления достаточно провести по области, где есть хотя бы одна клетка этого здания, и отпустить pointer.
- Удаленное здание исчезает с поля.
- Соответствующий пункт плана возвращается из `ПРИНЯТО` в `В ПЛАНЕ`.
- Прогресс генплана пересчитывается вниз.
- Удаление не считается ошибкой.
- Если drag начинается вне здания, работает обычная логика строительства и замены.

## Пустыри

- `ПУСТЫРЬ` - запрещенная клетка поля.
- Пустырь нельзя застраивать и нельзя включать в выделение для постройки.
- Пустырь не считается обязательной клеткой для победы.
- Пустырь всегда рисуется отдельным верхним overlay поверх зданий.
- Danger-selection через пустырь не должен выглядеть как новый большой пустырь.
- При выделении через пустырь главный reason ошибки: `Нельзя строить на пустыре`.
- Ни один сгенерированный rect и ни одно построенное здание не должны покрывать пустырь.

## Победа И Поражение

- Победа наступает, когда построены все проекты из плана, все обязательные клетки заняты, нет пересечений построек и ни одно здание не покрывает пустырь.
- Заблокированные клетки не требуют застройки.
- Кнопка `Долгострой` сбрасывает текущий уровень и выдает план проще.
- В одной сессии доступно 3 долгостроя.
- Третий долгострой показывает `Пятилетка провалена` и кнопку `Начать заново`.

## Tutorial Flow

- Tutorial повторяется при каждом новом открытии прототипа.
- `localStorage` для обучения не используется.
- Обучение состоит из коротких интерактивных этапов:
  1. `Первый фундамент` - протянуть простой прямоугольник.
  2. `План из нескольких корпусов` - построить несколько проектов из плана.
  3. `Пустырь` - построить участок, не задевая запрещенную клетку.
- Tutorial errors не должны загрязнять основную игровую сессию.
- Игрок может пропустить обучение и сразу перейти к обычному уровню.
- На mobile текущий feedback показывается отдельным штампом под `Планом пятилетки`.

## Адаптация Сложности

- Базовая сложность: `1..5`.
- Быстрый проход с малым числом ошибок повышает сложность.
- Тяжелый проход снижает сложность, но не ниже 1.
- Поздние уровни могут добавлять пустыри как часть валидного генплана.
- Уровни не должны состоять из полностью одинаковых площадей или форм.

## Генерация Уровней

- Сначала создается валидное скрытое разбиение доступной области на прямоугольники.
- Список проектов берется из площадей этих прямоугольников.
- Минимум две разные площади на уровне.
- Начиная со сложности 2 желательно минимум три разные площади.
- Одна площадь не должна занимать больше 70% списка.
- Rects не должны пересекать пустыри.
- Если генератор не смог создать валидный разнообразный уровень, используется проверенный preset.

## Визуальный Стиль

- Советский ретро-футуризм, проектный институт, строительный генплан.
- Top-down / pseudo-3D здания, бруталистские корпуса, бетонные крыши, дороги и технические метки.
- Палитра: бумажный бежевый, бетонный серый, графит, темно-зеленый, бордовый акцент, охра.
- Поле использует неяркие blueprint-подложки по сложности.
- Все стили игры должны быть scoped внутри `.stroika-game`.

## Visual Assets / Texture Pack

Ассеты лежат в:

```txt
src/assets/stroika/
```

Структура:

```txt
src/assets/stroika/
  README_TEXTURES.md
  ASSET_REPORT.md
  preview/
    stroika-preview.webp
  textures/
    blueprint_basic_01.webp
    blueprint_sector_01.webp
    blueprint_industrial_01.webp
    blueprint_restricted_01.webp
    concrete_roof_01.webp
    concrete_roof_02.webp
    panel_roof_01.webp
    institute_roof_01.webp
    industrial_roof_01.webp
    road_asphalt_01.webp
    road_service_01.webp
    wasteland_blocked_01.webp
    wasteland_blocked_02.webp
    foundation_01.webp
    foundation_danger_01.webp
    paper_noise_01.webp
    stamp_noise_01.png
```

- Preview карточки подключается через импорт `src/assets/stroika/preview/stroika-preview.webp` в `src/data/gamePrototypeSlots.ts`.
- Чтобы заменить preview, нужно заменить файл `src/assets/stroika/preview/stroika-preview.webp` с тем же именем и форматом. Рекомендуемый размер: `1600x900`.
- Чтобы заменить texture pack, нужно заменить файлы в `src/assets/stroika/textures/` с теми же именами. Основные текстуры: `512x512 WebP`; `stamp_noise_01.png` - `512x512 PNG with alpha`.
- После замены ассетов выполнить `npm run build`.
- Texture pack работает как дополнительный слой поверх CSS fallback: gradients нельзя удалять, иначе при ошибке загрузки ассетов поле станет визуально слабым.
- `wasteland_blocked_*` используется только для настоящих клеток `ПУСТЫРЬ`.
- Danger-selection через пустырь использует `foundation_danger_01.webp`, а не `wasteland_blocked_*`, чтобы временное выделение не выглядело как новый большой пустырь.
- Подробности по pack: `src/assets/stroika/README_TEXTURES.md`.

## Что Нельзя Добавлять В MVP

- Экономику, ресурсы, рабочих, магазин.
- Backend, авторизацию, сохранения в базу.
- Глобальную карту или полноценную кампанию.
- 3D/game engine/canvas, если DOM/CSS достаточно.
- Глобальные CSS-правки, влияющие на CV-лендинг.
